01

Tri veci, ktoré pri ručnom skladaní XML najčastejšie pokazia súbor.

Zložiť pain.001 XML v texťáku alebo vzorci v Exceli sa dá, ale stačí jedna maličkosť a banka súbor odmietne bez vysvetlenia.

  1. Stĺpce sa rozpoznávajú podľa názvu, nie podľa poradia.

    Generátor hľadá „IBAN“, „suma“, „názov“ a podobné hlavičky automaticky. Pri nezvyčajnom Exceli mapovanie skontrolujte a v prípade potreby ho ručne opravte vo výberoch nad náhľadom.

  2. VS, ŠS a KS nemajú v XML vlastné pole.

    Musia byť zapísané v EndToEndId v presnom poradí /VS.../SS.../KS.... Zlé poradie prevod nezastaví, ale príjemca si platbu nespáruje s faktúrou.

  3. Formát je jedna vec, pravidlá banky druhá.

    Po vygenerovaní beží nad súborom rovnaký engine ako v SEPA pain.001 Doctorovi: BIC, dátum splatnosti, diakritika a limit transakcií podľa vybranej banky.

03

Dve funkcie. Platby dnu, XML von, hneď skontrolované.

Žiadny server, žiadny API kľúč, žiadna registrácia. generator-pain001.js je čistý JavaScript: prečítajte si ho, forknite, alebo ho spustite vo vlastnom kóde či CI.

generator-pain001.js 0 závislostí 
import { parseRows, mapColumns, buildXml } from './generator-pain001.js';
import { diagnose } from './doctor-pain001.js';
// alebo globálne: const { parseRows, mapColumns, buildXml, bicFromIban } = window.SepaGenerator;

const rows = parseRows(textZExcelu);
const { payments } = mapColumns(rows);

const xml = buildXml({
  bank:     'tatrabanka' | 'slsp' | 'vub' | 'csob' | 'generic',
  payer:    { name, iban, bic },
  execDate: '2026-09-06',  // default: zajtra
  msgId:    undefined,       // default: auto ARL-YYYYMMDD-HHMMSS
  payments,       // {iban, amount, name, vs, ss, ks, message, bic, dateIso}[]
});

// súbor sa hneď kontroluje rovnakým engine ako SEPA pain.001 Doctor:
const report = diagnose({ xml, bank: 'tatrabanka' });

Parsovanie Excelu/CSV, mapovanie stĺpcov aj skladanie XML beží presne tak, ako ho volá formulár vyššie, vo vašom prehliadači. Neexistuje backend ani API kľúč, ktorý by obsah vašich platieb odniesol inam.

Poradie a povinnosť polí v XML vychádza priamo z technickej dokumentácie Tatra banky (pain.001.001.03, sekcie GroupHeader a PaymentInformation) a z tých istých pravidiel bánk, ktoré overuje SEPA pain.001 Doctor.

Zadarmo, otvorené, bez reklamy a bez sledovania nad rámec anonymných počtov použitia. Prípad, ktorý generátor spracuje zle, nahláste ako issue na GitHube.

05

Otázky, ktoré ľudia naozaj hľadajú.

Priame odpovede na otázky o generovaní SEPA pain.001 z Excelu.

Ako pripraviť Excel, aby ho generátor prečítal?

Označte stĺpce IBAN, suma a názov príjemcu (ideálne aj s hlavičkou v prvom riadku) a skopírujte bunky priamo do textového poľa (Ctrl+C, Ctrl+V): Excel ich prilepí oddelené tabulátormi a generátor to rozpozná automaticky. Rovnako funguje export do CSV oddeleného bodkočiarkou alebo čiarkou, alebo priame nahratie .csv/.txt/.tsv súboru. Ak automatické rozpoznanie stĺpcov netrafí správne pole, opravte ho ručne vo výberoch nad náhľadom platieb.

Kam sa zapíše variabilný symbol v SEPA XML?

pain.001.001.03 nemá samostatné pole pre variabilný, špecifický ani konštantný symbol. Generátor ich zapíše do PmtId/EndToEndId v poradí /VS.../SS.../KS..., presne podľa konvencie Národnej banky Slovenska: rovnakej, akú kontroluje aj sesterský nástroj SEPA pain.001 Doctor.

Ako naimportujem XML do Tatra banky, SLSP, VÚB a ČSOB?

Stiahnutý .xml súbor nahrajte v internet bankingu do formulára pre hromadný alebo dávkový príkaz (zvyčajne v sekcii Platby → Hromadné platby → Import súboru). Presné umiestnenie sa medzi bankami líši. Ak import zlyhá, skontrolujte najprv hlásenie, ktoré sa zobrazí hneď po vygenerovaní: ukáže presný element, ktorý banka odmietne.

Odosielajú sa moje platby niekam?

Nie. Parsovanie Excelu aj generovanie XML beží celé vo vašom prehliadači. IBAN, sumy ani mená sa nikam neposielajú, nástroj nemá backend. Jedinou sieťovou aktivitou je načítanie statických súborov stránky a anonymné počítadlo použitia (Umami), ktoré zaznamená len to, že prebehlo generovanie a aký bol výsledok kontroly, nikdy obsah platieb.

Koľko platieb môže byť v jednom súbore?

Generátor spracuje najviac 5000 platieb naraz. Ak majú platby rôzny dátum splatnosti, generátor ich automaticky rozdelí do samostatných blokov PmtInf podľa dátumu; Tatra banka aj tak obmedzuje jeden takýto blok na 500 transakcií, na čo kontrola po vygenerovaní upozorní.

Prečo banka odmietla súbor aj po kontrole?

Kontrola po vygenerovaní overuje formátové a bankové pravidlá, ktoré sú verejne zdokumentované, nie stav vášho účtu, existenciu účtu príjemcu ani interné limity banky (napríklad denný limit prevodov). Čistý výsledok preto nie je zárukou prijatia. Ak banka súbor aj tak odmietne, overte v prvom rade presné znenie chyby v internet bankingu.

In English: SEPA pain.001 Generátor is a free, client-side tool that builds a SEPA pain.001.001.03 XML batch payment file from payments pasted or uploaded from Excel/CSV, for Tatra banka, Slovenská sporiteľňa (SLSP), VÚB, and ČSOB. Every generated file is checked automatically by the same engine as the sibling tool, SEPA pain.001 Doctor. Nothing you paste is sent anywhere. See llms.txt or the source on GitHub.
